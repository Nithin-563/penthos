An AI coding agent must prevent API keys and secrets from being exposed through the following steps:  

1. **Avoid Direct Access to Secrets**:  
   - **Do not read or process files** containing secrets (e.g., `.env`, `config.json`, or code with hardcoded credentials).  
   - Use **static analysis tools** to inspect code without executing it, ensuring no secrets are extracted.  

2. **Isolate Execution Environments**:  
   - Run code analysis and modifications in a **sandboxed, isolated environment** with restricted permissions.  
   - Use **secure containers** (e.g., Docker) to prevent secrets from leaking to the host system.  

3. **Avoid Modifying Secret-Containing Code**:  
   - Scan code for patterns (e.g., `API_KEY`, `PASSWORD`) and **refuse to modify or touch files** that contain secrets unless explicitly allowed.  
   - Use **code linters** to flag secret usage and enforce policies against modifying such code.  

4. **No Logging or Echolocation of Secrets**:  
   - **Never log, print, or store secrets** in memory, logs, or outputs.  
   - Replace secret usage with **mocked or placeholder values** during testing or analysis.  

5. **Secure Access Controls**:  
   - Restrict the agent’s access to only the **necessary parts** of the repository.  
   - Use **role-based access control (RBAC)** to prevent unauthorized access to sensitive files.  

6. **Automated Secret Detection and Validation**:  
   - Integrate tools like **GitHub Secret Scanning** or **SonarQube** to detect secrets in code.  
   - After code changes, run **automated checks** to ensure no secrets are introduced or exposed.  

7. **Environment Isolation**:  
   - Use **environment variables** or **configuration files** to manage secrets, but **never expose them to the agent’s execution context**.  
   - Mock external APIs or services during testing to avoid real secret usage.  

By adhering to these principles, the agent ensures that secrets remain protected during inspection, modification, and testing, minimizing the risk of exposure.
